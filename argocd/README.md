# Nebulift Argo CD Resources

This directory contains the Argo CD resources used to bootstrap Nebulift's
GitOps-managed platform. The current supported entrypoint is the standalone
`nebulift-platform` Application, which deploys the MLOps platform from
`k8s/platform/base/`.

The older training `ApplicationSet` and per-environment training Applications
were removed after Phase 1b-2. Training Job manifests still live under `k8s/`
for future orchestration work, but Argo CD no longer reconciles them directly.

## Resources

- `projects/nebulift-project.yaml` — AppProject that allows the Nebulift repo,
  `nebulift-*` namespaces, and the Kubernetes resource kinds required by the
  platform (Deployments, Services, Ingresses, SealedSecrets, Jobs, and
  supporting config).
- `applications/nebulift-platform.yaml` — Argo CD Application that tracks
  `main` and syncs `k8s/platform/base/` into `nebulift-platform` with
  `CreateNamespace=true` and `ServerSideApply=true`.

## Prerequisites

Before applying the platform Application, install or verify the one-time
cluster bootstrap pieces documented in `cluster-bootstrap/README.md`:

- Sealed Secrets controller.
- A working Ingress controller. The homelab k3s cluster uses the bundled
  Traefik Ingress controller and `traefik` IngressClass.

Without these prerequisites, Argo CD can create the Application but sync will
fail because `SealedSecret` is unknown to the API server or the Ingresses have
no controller to serve them.

## Bootstrap

Apply the project first, then the platform Application:

```bash
kubectl apply -f argocd/projects/nebulift-project.yaml
kubectl apply -f argocd/applications/nebulift-platform.yaml
```

The Application targets `main`, so merges to `main` are the source of truth for
the platform. Argo CD automated sync is enabled with prune and self-heal.

## Verify

```bash
kubectl get application -n argocd nebulift-platform
kubectl get ns nebulift-platform
kubectl get deploy,svc,ingress -n nebulift-platform
```

The MLflow Deployment should pull the baked Phase 1b-2 server image:

```bash
kubectl get deploy -n nebulift-platform mlflow \
  -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
```

Expected:

```text
ghcr.io/taco-ops/nebulift-mlflow:latest
```

## Deprecated Training Applications

The old `nebulift-development` and `nebulift-production` Argo Applications
were generated by a removed `ApplicationSet`. Do not recreate them. Future
training automation should be introduced through a new phase-specific design
(for example, Argo Workflows in Phase 2) rather than reviving the old direct
Job reconciliation model.
